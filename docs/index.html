PersonaGuard helps researchers check whether a proposed personalization action has enough evidence to support it.

Researchers organize the evidence. The program applies rules to suggest a next step, with reasons and limits.

Can we use this experiment’s profile again later?

Here, a “profile” describes a person’s responses calculated from experiment records; it is not a validated long-term personal trait.

What we want to do

Save the profile from this experiment and use it in later sessions or other interfaces.

What the evidence shows

Stability across sessions and use across interfaces have not been tested. Coverage of the reference data cannot yet be adequately assessed.

Next step and why

Hold off on long-term storage and reuse in other settings.

Being able to compute a profile does not establish that it will still apply in a later session or another setting.

Five questions behind the review.

Open a question to see why it matters and how it changes the next step.

R1Does the conclusion reach beyond who, where, or what was tested?+

A result may depend on the people, setting, or information tested. If broader use is unsupported, limit its interpretation and use to that tested scope.

View formal conditions and code ↗
R2Do added sensors or automatic changes really improve the result?+

Compare against the alternative already tested for this task. When added benefit has not been demonstrated, keep that tested comparator.

View formal conditions and code ↗
R3Did a metric improve, or were user outcomes also evaluated in use?+

A better measurement or stated preference does not establish a benefit in actual use. If that is the only evidence for deployment, first run a preregistered study with users in context.

View formal conditions and code ↗
R4Has long-term reuse been checked for stability, transfer, and population coverage?+

A profile may not remain valid in another session or setting, and its reference data may not cover the relevant people. Missing or incomplete evidence means holding off on long-term storage and reuse elsewhere.

View formal conditions and code ↗
R5Is there direct evidence for this use, with user control or reversibility?+

Reversible personalization also needs direct user-outcome evidence that matches the proposed use. Only when all permission conditions are met and no other rule requires a restriction can it proceed within tested limits.

View formal conditions and code ↗

The next step may be to keep the comparator, gather evidence, limit the scope of use, or permit personalization when conditions are met. Insufficient evidence never means approval by default.

Execution order and permission boundaries+

R4 → R2 → R3 → R1 → R5

The questions above are numbered for explanation, not execution. Rules run in ascending priority order; the first match determines the result. The numeric priorities are 10, 20, 30, 40, and 90, respectively.

  • R1 limits the scope of a result; it does not authorize personalization.
  • R5 must independently satisfy all its permission conditions, with no higher-priority constraint matched.
  • When no rule matches, the program requests the specific missing evidence; it never approves by default.

What has the method been checked for?

What has been checked

  • The program follows the declared rules.
  • The same evidence produces repeatable decisions.
  • Materials from different studies fit a shared record format.

What still needs evaluation

  • Whether independent researchers can use the method consistently.
  • Whether the review is easy to understand and carry out.
  • Whether it improves real decisions, user outcomes, fairness, and safety.

Consistent execution does not mean real-world judgments are always correct.

See the check design and results+

The checks cover four proposed uses from this research and seven uses recorded by the authors from six external studies. The four uses are not four independent user experiments.

  • Record checks cover required fields, allowed values, source links, and rule execution. They do not verify whether the evidence itself is true or complete.
  • In 100 replays, the input order of rules, cases, and source records was shuffled. Rule priority values stayed fixed, and the resolver still sorted rules by priority before each decision. Decisions were unchanged; the check does not test changing the priorities themselves.
  • Each of the five rules was removed in turn. Every removal changed at least one decision; removing a restriction does not automatically authorize deployment.

Independent source studies do not mean the authors’ evidence coding has been independently verified. Agreement between researchers, completion time, usability, and real-world benefits remain to be evaluated.

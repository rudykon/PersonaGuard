# GitHub 上传前检查

公开内容以当前代码、配置、协议记录和复现说明为主。论文文件仅供本地使用，不上传 GitHub。

## 分享范围

| 内容 | 处理方式 |
|---|---|
| `src/`、`scripts/`、`tests/`、`configs/` | 纳入当前实现、测试与小型配置 |
| 双语首页、`docs/`、`paper_support/` | 纳入当前说明和具备分享权限的协议记录、汇总数据及源图 |
| `data/` | 仅纳入 `DATASET.md` 与 `stimuli/PROVENANCE.md` |
| `paper/` | 本地保留，不纳入 GitHub 发布内容 |
| `.local/`、`.venv/`、`artifacts/`、`checkpoints/`、`references/`、`archive/` | 本地材料，不上传 |
| 原始记录、视频、数组、权重、ZIP 与编译中间文件 | 不在普通代码仓库分发 |

## 本地只读检查

```bash
make check
make github-check
git status --short
git diff --stat
git diff --cached --stat
```

审计检查已跟踪文件与未忽略的新文件，不执行暂存、提交或上传。
本轮移除的文件会在 Git 状态中显示为删除；发布时应连同当前代码改动一起核对。
不要为消除缺失路径提示而恢复已删除实现。

忽略规则不会移除已经跟踪的文件。发布前需单独确认实际候选中不含 `paper/`，
并检查暂存内容和拟发布的提交历史。

## 分享前确认

- 核对数据、模型、源图和匿名示例的来源与分享范围。
- 本项目尚未选定整体开源许可证；由作者确认代码许可与第三方材料条件。
- 检查账户凭据、参与者信息和审稿身份；不要将本地令牌写入日志或仓库。
- 在没有私有数据与论文文件的副本中运行 `make check`。

目录整理与本地检查不代表已经创建远程仓库或上传文件。
